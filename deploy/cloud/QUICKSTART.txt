CarTrack — Cloud (DMSS-style, no on-site PC)  ·  QUICKSTART
============================================================

Camera --Easy4IP P2P--> Dahua cloud --P2P pull--> Azure VM (backend + YOLO/OCR ANPR)
                                                       |
                                                  HTTPS / WSS
                                                       v
                                                 Vercel frontend (UI)

Plate processing runs on the AZURE VM. Vercel only shows the dashboard.
No on-site PC, no router changes, camera is never exposed to the internet.


STEP 1 — Create the Azure VM
----------------------------
Azure Portal -> Create -> Virtual Machine
  Image : Ubuntu Server 24.04 LTS
  Size  : B2s  (2 vCPU / 4 GB  — required for live ANPR)
  Region: closest to the site (e.g. Qatar Central / UAE North)
  Networking -> allow inbound ports: 22 (SSH), 80 (HTTP), 443 (HTTPS)


STEP 2 — Free HTTPS domain
--------------------------
Go to https://www.duckdns.org , sign in, create a subdomain (e.g. "mycam"),
and copy the TOKEN shown at the top of the page.
Your domain will be:  mycam.duckdns.org


STEP 3 — SSH into the VM and get the code
-----------------------------------------
  sudo apt-get update && sudo apt-get install -y git
  git clone <YOUR_REPO_URL>
  cd "Car Tracking system/deploy/cloud"


STEP 4 — Run the installer (it does the rest)
---------------------------------------------
  sudo bash setup-cloud-vm.sh mycam.duckdns.org <DUCKDNS_TOKEN>

The script will:
  - install Docker + compose
  - open the firewall (22/80/443)
  - point your DuckDNS domain at this VM
  - create .env.cloud automatically
  - generate a SECRET_KEY automatically
  - ASK ONCE for the camera 'admin' password
  - build & start the backend + Easy4IP P2P tunnel + Caddy (auto-HTTPS)


STEP 5 — Verify
---------------
  curl https://mycam.duckdns.org/api/health        # should return OK
  docker compose -f docker-compose.cloud.yml logs -f backend
        # watch for the P2P tunnel reaching:  "Ready to connect"


STEP 6 — Point the Vercel frontend at the cloud backend
-------------------------------------------------------
Vercel -> Project -> Settings -> Environment Variables:
  VITE_API_URL = https://mycam.duckdns.org
Then Redeploy the frontend.

Open the Vercel site -> live feed: the camera now streams via the cloud and
ANPR runs on Azure, reachable from anywhere — exactly like DMSS.

NOTES
-----
- Why this works on Azure but failed on your PC: the P2P handshake needs open
  outbound UDP. Datacenter VMs allow it; your home/shop router blocked it.
- B2s is recommended for live ANPR. B1s (free) can VIEW the feed but is too
  small for full-speed plate recognition. Resize anytime in the Azure portal.
- Keep .env.cloud private — it holds the camera password and is git-ignored.
- If the site's public IP changes, DuckDNS is refreshed every 5 min by cron
  (added automatically by the installer).
